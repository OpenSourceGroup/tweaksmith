# Support payments (voluntary)

Tweaksmith support is **optional**, **browser-only**, and **never unlocks features**. The Mac app does not embed Razorpay, hold API keys, or verify payments.

## In-app flow

1. User opens **Support** in the app (sidebar or occasional voluntary prompt after successful tweaks).
2. The app opens `https://kamyab.co.in/tweaksmith/support` in the **system browser** via `NSWorkspace.shared.open`.
3. Optional preset amounts append an `amount` query parameter only (e.g. `?amount=499`). The app **never** reads return URLs or query params such as `?paid=true`.
4. Local prompt state (`SupportPromptController`) lives in `UserDefaults` only — no payment sync to servers.

Canonical URL: [`Tweaksmith/Core/ProjectLinks.swift`](../Tweaksmith/Core/ProjectLinks.swift) → `ProjectLinks.support`.

## Where Razorpay mode is configured

**Not in this repository.** Checkout, order creation, webhooks, and Razorpay credentials are implemented on **kamyab.co.in** (Kamyab website / edge worker backend). Stable **v0.1.0** expects **Razorpay LIVE** on that stack.

This repo documents the contract and release expectations only.

## Maintainer cutover checklist (website + Razorpay dashboard)

Complete these **outside** `OpenSourceGroup/tweaksmith` before calling Stable support payments “live”:

### Razorpay Dashboard ([dashboard.razorpay.com](https://dashboard.razorpay.com))

1. Finish **KYC / account activation** and enable **Live** mode for Kamyab Infotech Pvt Ltd.
2. Under **Live** mode, note the **Key ID** (public, starts with `rzp_live_`) — safe to expose to the browser checkout script.
3. Copy the **Key Secret** (live) — **never** commit; store only in host secrets.
4. Configure **Live webhooks** for the support checkout endpoint (URL and events must match the kamyab.co.in deployment).
5. Smoke-test a **small live INR payment** and confirm webhook + server-side verification (not `?paid=true` in the URL).

### kamyab.co.in deployment (secrets / environment)

Set or rotate these in the **production** environment for the site/worker that serves `/tweaksmith/support` (exact names may vary by deployment; align with the kamyab codebase):

| Variable | Purpose |
|----------|---------|
| `RAZORPAY_KEY_ID` | Live key id (`rzp_live_…`) for Checkout |
| `RAZORPAY_KEY_SECRET` | Live secret — server-side order verify only |
| `RAZORPAY_WEBHOOK_SECRET` | Verify webhook signatures in live mode |

**Remove or disable** test-only values (`rzp_test_…`, test webhook secrets) from **production** bindings. Keep test keys only on non-production/staging if you still need internal QA.

### Verify end-to-end

1. From a Stable build, tap **Support** → **Open support page** (or a preset amount).
2. Complete checkout in the browser; confirm success UI on kamyab.co.in.
3. Confirm the Mac app behavior is unchanged (no new features, no “paid” state in-app).

## In-repo hygiene

- Do **not** commit `rzp_live_*` secrets or live key secrets. CI scans non-doc source for `rzp_live_` and `rzp_test_` patterns.
- Release artifacts generated by `scripts/package-release.sh` no longer list Razorpay TEST as a known limitation once live cutover is done on the website.
